# Git Ignore Configuration Guide

This document explains what should be included in the `.gitignore` file for this project and the rationale behind each section.

## Project Structure Overview
- **Backend**: Node.js Express application
- **Frontend**: Vue.js/React frontend application  
- **AI Service**: Python machine learning models
- **Infrastructure**: Docker and Kubernetes configurations

---

## .gitignore Sections

### 1. Node.js Dependencies & Build Artifacts
```
node_modules/
npm-debug.log*
yarn-debug.log*
yarn-error.log*
dist/
build/
.next/
out/
```
**Why**: Dependency folders are large and can be reinstalled via `npm install` or `yarn install`. Build artifacts are generated and unnecessary in version control.

**Affected directories**: `backend/`, `frontend/`

---

### 2. Python Virtual Environments & Cache
```
__pycache__/
*.py[cod]
*$py.class
*.so
.Python
env/
venv/
ENV/
*.egg-info/
.installed.cfg
*.egg
.pytest_cache/
```
**Why**: Virtual environments are environment-specific and can be recreated. Python bytecode files are generated on runtime.

**Affected directories**: `ai-service/`

---

### 3. Trained Models & Data
```
*.pkl
*.joblib
```
**Why**: ML model files can be large. Consider:
- **Keep in Git**: Small models (<5MB) with Git LFS
- **Ignore**: Large models, use cloud storage or model registries instead
- **Decision**: Currently ignored; store models separately

**Affected directories**: `ai-service/models/`

---

### 4. IDE & Editor Files
```
.vscode/
.idea/
*.swp
*.swo
*~
.DS_Store
```
**Why**: IDE configurations are developer-specific and shouldn't be enforced across the team.

**Note**: If team uses same VS Code extensions, consider tracking `.vscode/extensions.json`

---

### 5. Environment Variables & Secrets
```
.env
.env.local
.env.*.local
```
**Why**: CRITICAL - Never commit credentials, API keys, database passwords, or connection strings.

**Current files to protect**:
- Database credentials
- AI service API keys
- OAuth tokens
- JWT secrets

---

### 6. Upload Directories
```
backend/uploads/
uploads/
```
**Why**: User-uploaded files are runtime data, not source code.

**Current**: Backend expects uploads directory for file storage.

---

### 7. Logs & Temporary Files
```
logs/
*.log
*.tmp
*.temp
demo-trigger.txt
```
**Why**: Generated at runtime, not needed in version control.

---

### 8. Build Outputs
```
backend/dist/
frontend/dist/
ai-service/dist/
```
**Why**: Generated from source code; can be rebuilt anytime.

---

### 9. Backups
```
backups/
```
**Why**: The `backend/backups/` folder contains database backups that shouldn't be in version control.

**Recommendation**: Store backups in cloud storage (AWS S3, Azure Blob Storage) instead.

---

### 10. Test Coverage Reports
```
coverage/
.nyc_output/
```
**Why**: Generated by test runners; not needed in repository.

---

### 11. Database Files
```
*.db
*.sqlite
*.sqlite3
```
**Why**: Local database files should never be committed. Use migrations instead.

---

## Files to Keep in Git

### ✅ DO Track These
- `package.json` & `package-lock.json` (or `yarn.lock`)
- `requirements.txt` (Python dependencies)
- `docker-compose.yml` & Dockerfile configurations
- Kubernetes manifests (`k8s/`)
- Configuration templates (e.g., `db.js`)
- Migration files
- `.gitignore` itself

### ❌ DON'T Track These
- `.env` files with actual values
- Node modules or venv directories
- Build outputs or dist folders
- Large binary files (models, datasets)
- IDE-specific settings
- OS-generated files

## Security Best Practices

1. **Secrets Management**
   - Use `.env.example` to show required variables
   - Document all required environment variables in README

2. **Credential Scanning**
   ```bash
   # Optional: Install git-secrets to prevent commits
   brew install git-secrets
   git secrets --install
   ```

3. **Before Committing**
   - Review `.env` files are NOT staged
   - Verify no hardcoded API keys in code
   - Check for `console.log()` with sensitive data

## Updating .gitignore

If you add new entries to `.gitignore`, they only apply to untracked files. To stop tracking an already-committed file:

```bash
git rm --cached <filename>
git commit -m "Stop tracking <filename>"
```

To stop tracking all entries in new .gitignore rules:

```bash
git rm -r --cached .
git add .
git commit -m "Update .gitignore"
```
