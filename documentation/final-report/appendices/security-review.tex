\section{Authentication Risks}
Tokens are stored in browser \texttt{localStorage}. This is simple and common in student projects, but it increases exposure if a cross-site scripting bug reaches the page. The backend applies XSS cleaning and Helmet, yet the safer long-term design would be secure, HTTP-only cookies or a carefully reviewed token storage strategy. The current implementation also depends on secret strength and correct production environment management.

\section{Authorization Risks}
Role-based access is visible in routes, but role checks alone do not solve object-level authorization. The project partly addresses this with access helpers and tests for objective visibility and task privacy. The remaining risk is uneven enforcement across a large route surface. A future security pass should review every endpoint with the question: can a user change the identifier in the URL or body to access another employee's data?

\section{Data Privacy Risks}
The platform handles sensitive HR data: evaluations, comments, scores, improvement plans, bonus/penalty records, and employee feedback. The report does not include personal data, secrets, or real employee content. For production, the system would need retention policies, access logging review, encryption-at-rest verification, backup protection, and formal HR data-processing rules.

\section{AI Privacy Risks}
Generative AI requests send compacted performance context to an external provider depending on \texttt{AI\_PROVIDER}. The code limits input size and asks the provider to use supplied data only, but it does not by itself guarantee provider-side privacy. A production deployment should document which provider is used, what data is sent, whether logs are retained, and how employees are informed.

\section{Deployment Risks}
Kubernetes manifests reference \texttt{backend-secret}, but the repository does not include secret templates. That is appropriate because secrets should not be committed. However, deployment repeatability would improve with a sanitized environment-variable template and secret-management instructions. The CI workflow includes Trivy scans, but monitoring, alerting, and backup automation are not present.
