\section{Shared Application Shell}
The frontend shell is implemented with \texttt{DashboardLayout.jsx}, \texttt{EnterpriseSidebar.jsx}, and \texttt{TopHeader.jsx}. This creates a stable protected layout for role-aware navigation, page title display, active cycle state, search, notifications, and profile menu. The route file groups sidebar items by sections: Main, Annual Cycle, People, Development, and Management.

\section{Authentication and API Clients}
\texttt{AuthContext.jsx} owns session behavior. It reads and writes access tokens, refresh tokens, and a compact current-user object from browser storage. It pings \texttt{/auth/me}, refreshes access tokens through \texttt{/auth/refresh}, and clears the session on logout or invalid refresh. \texttt{frontend/src/services/api.js} creates the main Axios instance, adds authorization headers, retries eligible \texttt{401} responses once after refreshing the token, caches selected GET requests, and clears cached GET responses after mutations.

\section{Goal and Objective UI}
The objective UI is distributed across \texttt{GoalsPage.jsx} and components under \texttt{components/goals}. The creation modal includes weight selection and capacity awareness. The detail panel supports tabs for details, KPIs, updates, comments, and activity. The table exposes status, category, weight, progress, KPI count, and expanded details. Manager review and evaluate modals separate approval/review actions from ordinary editing.

\section{Work Management UI}
The task page and task components implement a compact operational workspace. The model and UI support task status, workflow stage, progress percentage, priority, due date, linked objective, team, recurrence, and time tracking. This module matters for the final evaluation because task completion and check-in evidence are used by scoring/evidence services.

\section{Evaluation UI}
Final evaluation views are separated between employee and manager perspectives. The manager view supports generation, update, recalculation, score adjustment, HR submission, and AI-assisted draft use. HR validation has its own page so HR can review pending and returned items without mixing manager-owned editing responsibilities.

\section{UI States}
The repository contains shared \texttt{EmptyState}, \texttt{LoadingSkeleton}, \texttt{ErrorBoundary}, \texttt{Toast}, \texttt{Badge}, and \texttt{ConfirmDialog} components. This indicates that loading, empty, error, confirmation, and feedback states were considered as reusable product behaviors rather than repeated inline messages.
